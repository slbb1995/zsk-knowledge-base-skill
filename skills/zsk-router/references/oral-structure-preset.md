# 新建知识库预置口播结构

每个新客户知识库默认拥有一份完整、可独立维护的口播结构库。入口仍是 `zsk-router`，不新增用户入口或确认停点。

## 资源与范围

- 随 ZSK 安装包分发：`shared/assets/oral-structure-v1/package.json` 和同目录的 `口播结构/`。
- 初始版本 `1.0.0`，22 份 Markdown：索引、3 份方法论、9 种基础结构、5 种增强机制、时长适配、2 份验证反馈规则和1种待验证结构。
- 保留原文及历史来源状态。包内 `source_ids` 是原方法材料的历史引用，不是客户 01 的来源登记，也不代表在该客户账号验证有效。
- 预置包提供内容方法；此次不改变对标拆解、Content Slim 检索或 Writer。

## 新建库执行

1. 使用 `shared.stage11_bootstrap.FirstRunBootstrap` 检查新目标。已存在的目标不复用或覆盖。
2. 读取预置包，校验清单、版本、全部文件摘要及内部双链。缺件、损坏或无法解析的链接在创建前停止。
3. 原有预览显示“包含完整口播结构库”，确认绑定当前模板版本及包摘要；内容变化后必须重新展示预览，不能沿用旧确认写入。
4. 创建骨架和基础 Content 清单。Obsidian 在 `04-内容方法库/口播结构` 写入完整副本；飞书在 04 下创建相同层级的知识库节点与云文档。
5. Obsidian 保留双链。飞书先创建全部目标节点，再把双链转换为当前客户空间内的文档链接，章节链接显示章节名称并打开所属文档；目录节点含可点击子项索引。写入 Markdown 时显式传入 `<title>`，将带编号的节点名与原正文 H1 分开，防止平台用正文标题重命名节点。
6. 逐项回读节点、正文与链接。只有全部通过后才在 06 写入 `oral-structure-installation` 安装记录：Obsidian 为 JSON 文件，飞书为 JSON 内容文档。
7. 安装记录包含包版本、包摘要、原压缩包摘要、来源归属、每份文件的原始元数据、安装引用与安装时摘要。飞书正文不展示 YAML 元数据，原始元数据保存在这份独立记录中。记录回读通过后才报告完整建库成功。

## 已有库与失败

- 公共包更新只影响之后的新库。客户副本允许独立修改，不向公共模板或其他客户传播。
- 旧库检查、资料入库、Content 连接和补骨架均不触发预置安装；补装和升级留待单独授权与设计。
- 同名目录、文档或安装记录冲突时停止，不覆盖、不默认复用，也不补齐已有目录。
- 远端创建、写入或回读失败时保留已创建对象，返回真实库位置和“预置未完整完成”。安装记录本身若写入后回读失败也不能报告成功；已有半成品不会被自动删除或覆盖。
- `Stage2Router` 和 Adapter 的 `create_skeleton` 是底层骨架工具，不能替代首次建库入口或作为完整预置成功证据。

## 维护与验证

修改预置包时同时更新版本、清单与每份正文的 SHA256。正文摘要按 UTF-8、LF 换行计算，以兼容 Git 的 Windows 换行转换。不得只更新文档而保留旧清单。

相关测试：`tests/test_oral_structure_preset.py`、`tests/test_oral_structure_feishu.py`、`tests/test_install_doctor.py`。飞书离线 CLI 合同测试只能证明请求编排、结构、链接和失败处理；真实飞书渲染与服务端行为需要远端验证后才能声明已实测。

飞书回读要同时检查 Wiki 节点名和完整正文。平台会在文档名与首个 H1 相同时省略单独的 `<title>` 标签；允许这种导出差异，但仍须保留正文标题层级、表格结构、内容顺序、代码和真实链接目标。
