# 从选题到全文：角度与结构使用指引

角度名称来自用户提供的八种选题提示词及讲解；定义整理、结构衔接和教学示例为编辑综合。示例不是客户事实，采用不代表已验证传播效果。

### 2.1 一篇内容里的四种分工

| 层次 | 解决的问题 | 例子 |
| --- | --- | --- |
| 主题与意图 | 客户究竟想说什么？ | 希望老板理解：员工用 AI 变快，还需要检查团队协作。 |
| 切入角度 | 目标观众为什么现在愿意听？ | 使用了提效工具，老板却可能承担更多审核。 |
| 主体结构 | 用什么顺序把问题讲成立？ | 从具体症状，进入误判、判断依据和优先修正动作。 |
| 局部增强 | 哪一处需要更好理解或跟上？ | 先展示一份返工记录，再解释返工发生在哪里。 |

角度决定关注点，结构承担论述，增强机制帮助表达。它们共同服务于客户本篇想表达的意思。一个角度可以对应多种结构，同一个结构也能承接不同角度。

“干货／话题／转化”是已有 Writer 的主模式；成本、反差等是内容角度，不是新增的 Writer 模式。

### 2.2 每次判断什么

拿到“选题、对标、我的想法”后，先回答以下问题。它们是内部选材与方向设计的思考顺序，不是让客户额外填写的表格。

1. **客户要保留的意思是什么？** 原始选题、明确观点、读者对象、希望读者理解或采取的行动分别是什么？哪些只是写作要求？
2. **观众正在意什么？** 是花了钱却没解决问题、第一次做不会判断、遇到与预期相反的结果，还是想理解一件陌生的事？必须能回到本篇主题。
3. **现有材料真正有什么？** 对标里有可迁移的问题、观点、推进方式还是只有一句吸引人的话？哪些事实能用，哪些属于他人的身份或案例？
4. **原来的角度是否已经合适？** 合适就保留；需要调整时，说明读者能更快理解什么或更愿意继续了解什么，不为变化而改写。
5. **开头引出的兴趣如何兑现？** 正文需要解释原因、演示过程、比较方案还是讲清一段变化？材料是否支持？
6. **在哪里结束才算完整？** 这篇最终要回答哪个问题，落下哪个判断，或给出哪个可执行动作？

有对标时同样做这次判断。对标提供参考，客户的明确意图决定取舍；若两者存在影响核心立场的冲突，应在方向中说明，不能静默把客户带成对标作者的观点。

“每次判断”不要求逐个试完八种角度。先从当前材料里找最相关的关注点；只有确实存在两种不同的讲法，才形成两个供客户选择的方向。

### 2.3 判断结果要具体到本篇

不要停在“使用成本角度、增强反差、结尾升华”。至少说清：

- 对谁说，以及他正在面对的具体问题。
- 本篇准备保留的核心意思。
- 用哪个具体问题或落差进入，为什么适合。
- 正文按什么顺序推进，各部分增加什么。
- 对标和所选方法分别贡献什么。
- 需要哪些事实，当前哪些仍没有依据。
- 最后要回答或落下什么。

例如，“成本角度＋对比决策”的具体用法可以是：围绕同一项工作，比购买费用、后续整理和维护负担；先明确任务，再用同一标准比较两条路线，最后按实际使用频率给条件化建议。若没有费用和耗时数据，就不能宣称哪条路线一定更省。

这些判断应融入现有详细方向及其客户投影，不另建第二份 Writer 材料包。本文中的示例开头用于解释方法，不要求 Content 在 Gate A 提前写正文。

### 2.4 从角度挑结构，先看“需要怎样回答”

| 本篇需要完成的回答 | 可考虑的现有结构 | 进入条件 |
| --- | --- | --- |
| 解释为什么一个惯常理解不完整 | ORAL-STR-001 痛点镜像与反常识解法 | 有具体痛点、旧解释及能够说明的新理解 |
| 教会一个可验证动作 | ORAL-STR-002 教程拆步与结果兑现 | 有步骤、前置条件和结果检查方法 |
| 讲本人怎样经历一次变化 | ORAL-STR-003 经历反转与方法提炼 | 有本人真实经历及关键动作、变化依据 |
| 查一个问题先查哪里 | ORAL-STR-004 诊断纠偏 | 有症状、候选解释及优先核对依据 |
| 展示产品或服务怎样解决问题 | ORAL-STR-005 产品教程与轻转化 | 有真实功能、过程或演示及其限制 |
| 帮助理解一个抽象关系 | ORAL-STR-006 类比观点快打 | 类比双方存在可说清的对应关系 |
| 说明一个判断有哪些依据 | ORAL-STR-007 一个结论多个证据 | 有同主题且支持该判断的独立依据；使用状态另核 |
| 帮助在方案间作出选择 | ORAL-STR-008 对比决策 | 同一任务、可比维度和各方案真实条件 |
| 说明一项真实客户交付 | ORAL-STR-009 客户案例证明 | 有可使用的客户场景、过程与结果证据 |

以上是候选关系，不能按题目出现“便宜”就自动选对比结构，或出现“第一次”就自动选教程。角度选择和结构选择都要回到本篇目的及材料。

已有同行的推进方式适合时可以沿用，不为凑编号强行再选一张基础结构。003 和 009 不因故事更吸引人就降低材料要求；006 的类比帮助理解，不代替证据。

**使用状态提示：** 007 与增强机制为 experimental_reference，需明确实验授权；以下组合只说明方法关系，不表示已验证效果。

### 4.1 组合速查

表中结构只表示值得考虑的路线，最终由目的和材料决定。

| 角度 | 观众主要想知道 | 可考虑的结构 | 结尾应完成的事 |
| --- | --- | --- | --- |
| 成本 | 少付什么、多付什么，怎样做值得？ | 008 比较；002 操作；004 查原因 | 给出成本判断条件或可验证动作 |
| 特定人群 | 像我这样的人，从哪里开始？ | 002；004；008；真实案例可用 009 | 给出适合该处境的下一步 |
| 最差／负向体验 | 差在哪里，能否避免？ | 004；008；001 | 给出可识别的失败信号或选择标准 |
| 头牌／标杆 | 有什么值得学，哪些不能照搬？ | 002；008；条件满足时 005／007 | 提炼可迁移做法及适用范围 |
| 猎奇 | 这个现象怎样发生？ | 002；004；006；演示可用 005 | 解答疑问，给出验证或理解方式 |
| 反差／对立 | 为什么和预期不一样？差异意味着什么？ | 001；004；008；真实过程可用 003／009 | 形成更完整的判断或检查顺序 |
| 荷尔蒙／吸引力 | 我怎样表达自己，如何理解具体偏好？ | 008；002；条件满足时 001／003 | 给出自主、具体且不承诺他人反应的选择 |
| 怀旧与古代 | 过去为何如此，今天能借鉴什么？ | 008；003；006；条件满足时 007 | 区分可迁移做法与年代条件 |

### 4.2 同一个角度，为什么不能固定套一套结构

“成本”主题中，客户问“选哪个”时，需要公平比较；问“怎么少做一步重复劳动”时，需要教程；问“为什么投入增加却没改善”时，需要诊断。三种都可以用成本进入，正文要完成的任务却不同。

“反差”也一样：希望读者理解一个区别，可以用 001；希望解决正在发生的问题，可以用 004；希望说明一次真实改变，可以用 003 或 009。没有真实过程，就不能为了写得有戏选择故事结构。

先写清本篇的问题和可用材料，再选路线。不要根据行业或单个关键词，把八个角度硬绑定到固定结构。

### 4.3 同一个结构，可以接不同角度

以 008 对比决策为例：

- 接成本：比较同一任务下的投入与后续负担。
- 接人群：比较不同条件的人适合哪种方案。
- 接标杆：比较标杆特点带来的价值与代价。
- 接怀旧：比较过去与今天的条件和做法。

无论接什么角度，都保留 008 的基本要求：共同目标、可比维度、真实差别、条件化建议。角度不能成为隐去另一方案优点的理由。

### 4.4 角度之间的组合

通常先确定一个主要关注点，再判断其他因素是否有必要。这里不设强制的“每稿必须一个主元素加一个辅元素”。

例如“新手参加线下实践活动，要不要先买全套工具”：新手处境可以限定受众，成本可以帮助讨论投入，正文仍只回答当前任务下怎样准备。没有必要再加入名人、怀旧和性别对立。

如果加入一个元素后，文章开始回答另一个问题，先检查是否已经偏离批准方向。多个元素不是质量指标。

### 4.5 增强机制只处理局部需要

下表是作用位置说明，不改变现有实验状态和使用权限。

| 现有机制 | 可以怎样服务角度与主线 | 什么时候不需要 |
| --- | --- | --- |
| ENH-001 信息缺口 | 猎奇／反差开头提出一个具体未知，正文前段尽快回答 | 需要立即给出明确操作或紧急信息时，不故意延迟 |
| ENH-002 嵌套开放回路 | 较长的比较或诊断中，围绕同一总问题逐段回答子问题 | 短稿一个问题就能讲清时 |
| ENH-003 分段与信号提示 | 成本比较、教程或多条件选择中，提示“先看什么，再看什么” | 路标比实际内容还多时 |
| ENH-004 峰终设计 | 把最有用的判断或演示突出，并让结尾回应开头 | 已自然收束时，不额外制造戏剧高潮 |
| ENH-005 模式中断 | 从抽象解释切到具体证据、演示或问题回指，带来新信息 | 只想加音效、大喊或无关转折时 |

增强机制应解决一个可指出的问题。例如“比较项较多，需要路标”比“增加三个爆款技巧”更可执行。基础内容已经清楚时，可以不增加增强机制。

### 5.1 开头吸引力来自具体任务

开头应尽快让目标观众知道：这条内容与什么处境有关，接下来能理解或完成什么。

| 平直或空泛写法 | 调整方向 | 必须跟上的正文 |
| --- | --- | --- |
| 今天给大家讲表单设计 | 从一次具体填写困难进入 | 找到困难的位置、原因和可改动作 |
| 这个工具非常高效 | 明确它帮助完成哪项操作 | 展示过程及结果检查，不只列功能 |
| 所有人都忽略了一个秘密 | 指明当前材料能支持的具体疑问 | 尽快解释，不虚构行业隐瞒 |
| 新手一定要看完 | 写出新手会遇到的具体场景 | 按他的起点解释，不用专家术语跳步 |

若开头改成“哪一个更好”，正文就需要比较；改成“为什么”，正文就需要解释；改成“怎么做”，正文就需要动作与验证。吸引力越强，越要明确承诺了什么。

### 5.2 正文要增加内容，不只是增加语气

每段至少承担一种实际作用：补原因、解释区别、展示依据、给动作、说明条件、推进变化。不要用不同说法连续强调同一个痛点。

可以把概念落成读者能看到的对象与动作，例如把“提高协作效率”展开为“交给谁、按什么标准完成、由谁确认”。但这些对象和动作需来自本篇任务或材料，不能凭空添加客户服务承诺。

段落长短按信息需要安排。编号、对话、比喻、反问都可以用，不把它们变成每篇必备装饰。

### 5.3 结尾把本篇主要问题说完

| 前文主要任务 | 合适的收尾 | 容易仓促的收尾 |
| --- | --- | --- |
| 解释原因 | 回到开头现象，落下有依据的判断或优先核对项 | 列完原因突然说“好了，就这些” |
| 教操作 | 说明如何确认做对，或下一次从哪个动作开始 | 只喊“赶紧试试”，没有完成标准 |
| 做比较 | 说明什么条件下选什么，哪些仍需确认 | 泛泛说“适合自己的才是最好的” |
| 讲经历／案例 | 提炼可迁移做法与不能照搬的条件 | 只宣布成功或感谢观看 |
| 讨论处境／观点 | 回扣核心立场，让读者带走一个清楚判断 | 又开启一个新议题或强行升华 |

判断完整性的一个方法：去掉“点赞、关注、评论区聊聊”后，前面的内容是否已经把话说完？如果还没说完，应补论述的最后一步。

结尾可以是自然的判断、动作或适用条件，不必额外写金句。客户需要互动时，问题应当与本篇主题有关，而非通用的“你怎么看”。

### 5.4 把七个功能锚点用于设计和自查

设计时可借七个锚点检查有没有讲清：开场承诺、对象感、核心问题、兑现路径、依据、必要的节奏提示，以及收尾。它们不是七段模板。

提交前回看：开头的兴趣是否得到回应；每段是否推进主问题；结尾停在这里是否完整；哪些表达超出了材料。这仍是作者完成写作的一部分，不增加独立 Reviewer 或循环改稿链。

### 5.5 简短方向设计示例

以下只演示方法怎样进入方向说明，不是程序字段或新增客户表单：

> 这篇讲给已经让员工用 AI、但仍承担大量审核的负责人。保留客户关于协作问题的判断，从“交稿快了、待审更多”的落差进入。正文先区分数量增加和返工，再依据现有记录确定先查哪一处，最后给出一个可执行的检查动作。采用诊断结构，不承诺换一套标准就能解决所有问题；若缺少记录，保留核对顺序，不把某个原因写死。

这段说明比“反差角度＋诊断结构＋行动结尾”多交代了本篇的推进关系。具体字段、方向选定及批准顺序遵守 Content 口播 Slim 的当前合同。
