# 结构选择矩阵

> 使用说明：稳定方法论参考；用于筛选基础结构，不直接作为口播主线候选。

结构选择不是单选题。可以先挑出一到三个方向，分别看哪一种最能承接现有素材；也可以确定一条主线，再借用另一种结构的开头、证明方式或结尾。

## 按内容目标找方向

| 观众看完要获得什么 | 可以优先尝试 | 有这些素材会更好写 |
|---|---|---|
| 发现旧认知不完整，并得到新解法 | [[ORAL-STR-001_痛点镜像与反常识解法]] | 具体痛点、旧做法、新解释、动作 |
| 学会完成一件事 | [[ORAL-STR-002_教程拆步与结果兑现]] | 前置条件、动作步骤、验证标准 |
| 从经历中获得方法 | [[ORAL-STR-003_经历反转与方法提炼]] | 本人真实经历、转折、结果、边界 |
| 找到问题的优先原因 | [[ORAL-STR-004_诊断纠偏]] | 症状、误判、原因证据、修正顺序 |
| 看懂产品或服务怎么解决问题 | [[ORAL-STR-005_产品教程与轻转化]] | 场景、演示、限制、行动入口 |
| 用熟悉事物理解抽象观点 | [[ORAL-STR-006_类比观点快打]] | 映射关系、观点、边界 |
| 快速理解一组信息意味着什么 | [[ORAL-STR-007_一个结论多个证据]] | 同主题事实、来源、日期、含义 |
| 在多个方案之间做条件化选择 | [[ORAL-STR-008_对比决策]] | 同一比较轴、优势、限制、条件 |
| 理解真实交付过程与能力 | [[ORAL-STR-009_客户案例证明]] | 授权、脱敏、过程与结果证据 |

## 素材不完整时的替代方式

- 缺少本人经历：先写“经历结构草图”，或者改用观点、教程、诊断结构。
- 缺少客户案例细节：只保留“问题—过程—变化”的框架，不把假设写成真实客户故事。
- 缺少完整数据：可以写判断思路、核对方法或待补证据位置，暂不下确定性结论。
- 只有观点、没有理由：先补理由，也可以用类比或提问帮助把观点展开。
- 多个结构都合适：分别写简版，也可以选一个做主线、另一个提供局部模块。

## 组合增强机制

增强机制用于调整注意力、节奏和理解成本。可以不使用，也可以根据内容长度组合使用；重点是每个机制都服务于主线。名单见 [[00_结构索引与AI调用规则#增强机制]]。
