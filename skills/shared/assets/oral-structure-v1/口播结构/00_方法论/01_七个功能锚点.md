# 七个功能锚点

> 使用说明：稳定方法论参考；用于方向设计和写后检查，不直接作为口播主线候选。

七个功能锚点用于设计时检查思路，以及写完后检查表达。它们不是固定段数，也不要求每条全部展开。同一段可以承担多个作用，短稿可以合并功能。

| 锚点 | 它帮助回答什么 | 常见呈现方式 |
|---|---|---|
| 开场承诺 | 为什么现在值得继续听？ | 具体问题、结果、判断、冲突或信息缺口 |
| 对象感锚定 | 这段内容与谁有关？ | 人群、场景、任务或共同处境 |
| 核心问题 | 这一条主要在讲什么？ | 一个主问题，其他信息围绕它服务 |
| 兑现路径 | 开头提出的东西怎样被讲清楚？ | 原因、步骤、比较、故事或演示 |
| 证据或案例 | 观众为什么愿意相信？ | 事实、来源、真实经历、演示或清楚的推理 |
| 注意力重置 | 中途怎样重新建立兴趣？ | 转折、问题回指、分段提示、画面或节奏变化 |
| 收尾与可带走的内容 | 主要问题是否说完，观众留下什么？ | 明确判断、兑现结果、条件建议、动作、相关问题或自然结束；CTA 可选 |

## 怎样选择

- 教程和观点内容通常更需要“核心问题＋兑现路径”。
- 经历和案例内容通常更需要“对象感＋证据或案例”。
- 中长内容可以增加“注意力重置”，短内容不必为了凑锚点强行转折。
- 结尾可以是行动，也可以是判断、余味或自然收束，不必每次都安排 CTA。
- 一个锚点可以承担多个作用，同一作用也可以分散在不同段落。

## 写完后的自查

先确认正文仍在表达客户认可的意思，再检查：开头提出的兴趣是否得到回应；每段是否增加了信息或推进；结尾是否完成了本篇任务；是否加入了材料没有支持的事实。发现问题就处理对应段落，不为凑锚点重写整篇，不增加独立审稿环节。

## 容易写坏的地方

- 用夸张情绪代替承诺。
- 同时打开太多问题，导致主线变散。
- 把作者身份当作事实证据。
- 用点赞量推断完播率。
- 在价值还没有出现前连续要求关注、点赞或私信。
