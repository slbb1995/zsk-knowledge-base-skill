# 教程拆步与结果兑现

> 使用说明：基础结构，可作为口播主线候选；来自多来源模式归纳。

## 用途

让观众在当前场景中完成一项操作，并知道如何判断自己是否做对。

## 适合的内容

- 目标结果明确。
- 操作能拆成连续动作。
- 每一步有前置条件和完成标准。

如果问题仍未诊断清楚，先用 [[ORAL-STR-004_诊断纠偏]]。

## 功能顺序

```text
结果承诺
→ 前置条件
→ 步骤一至三
→ 结果验证
→ 常见错误
→ 第一个可执行动作
```

## 可以重点关注

- 开头先说清楚观众能完成什么，再进入步骤。
- 操作结果、截图或现场演示都可以帮助观众判断是否做对。
- 步骤编号、“完成后你会看到……”或画面变化都可以承担节奏提示。

## 时长

- 15—30 秒：一个关键动作加验证。
- 30—60 秒：通常适合一到三步。
- 60—120 秒：增加前置条件、失败分支和回退。

## 素材不足时怎么用

工具、权限或前置条件不完整时，可以先写教程骨架，并把缺口标成变量；也可以把主题改成“开始前先确认什么”，避免写成人人都能直接完成。

## 容易写坏的地方

- 把概念当步骤。
- 讲“三步”但每步又展开五个分支。
- 只说做法，不告诉观众如何验证。
