# 客户案例证明

> 使用说明：基础结构，可作为口播主线候选；来自多来源模式归纳。

## 用途

从客户真实问题出发，说明约束、诊断、实施过程和结果变化，使观众理解交付能力如何落地。

## 案例材料的三个层次

1. **场景层**：客户遇到了什么问题，受到哪些条件限制。
2. **过程层**：怎样判断、怎样行动，中间发生了什么变化。
3. **结果层**：哪些来自客户反馈，哪些是项目观察，哪些有数据支持。

材料还不完整时，可以先写脱敏后的案例框架或通用案例结构；等真实内容补齐后，再把它写成具体客户案例。身份、联系方式、健康、保单、财务和商业秘密等可识别信息不需要进入叙事。

## 功能顺序

```text
脱敏后的客户场景
→ 原始问题与约束
→ 诊断依据
→ 实施动作
→ 结果与证据状态
→ 哪些因素不能归因
→ 可迁移方法与下一步
```

## 可以重点关注

- 客户场景承担对象感，不能靠暴露身份增加真实感。
- 过程与结果承担兑现。
- 原始记录、客户确认和项目数据承担证据。
- 阶段变化承担注意力重置。

## 时长

- 45—90 秒：一个问题、一个关键动作、一个结果。
- 90—180 秒：增加约束、过程、结果边界和可迁移方法。

## 容易失真的写法

- 把公共案例改写成自己的客户。
- 机械替换行业、客户或效果数据。
- 把多因素结果全部归因给服务。
- 为戏剧性补造对话、冲突和数字。
